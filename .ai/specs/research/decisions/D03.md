# D03 — PostgreSQL becomes the source of truth; S3 stores raw MIME
- Date, owner: 2026-09-21 (decision recorded in docs/production-readiness-plan.md §1–2, written 2026-09-04); ownership confirmed by Kamil Mastalerz in the discovery session
- Context and the options weighed: today all state lives in `data/prototype/state.json` (single process, whole-file rewrite). The plan weighed JSONB-in-Postgres shortcuts vs. normalized tables.
- Decision and why: PostgreSQL holds conversations, messages, comments, drafts, knowledge versions, archives, notifications, operations, and settings as separate records; S3 (private, AWS-SDK-compatible endpoint) stores immutable incoming/outgoing MIME with key, size, SHA-256 in the database. Import writes MIME to S3 first, then commits message + IMAP cursor in one transaction. Knowledge content stays in Postgres; `.md` copies end; export on demand.
- Consequences, and what would make us revisit it: enables multiple replicas; breaks the file-format contract in BACKWARD_COMPATIBILITY.md §3 by design — that migration is the required path. Clean start (D04) removes data-migration work.
- Status: active
