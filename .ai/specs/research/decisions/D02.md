# D02 — Staged auth: e-mail+password (ADR-0002) rules the api MVP; Google OAuth applies at public access
- Date, owner: 2026-09-21, Kamil Mastalerz (readiness plan §4 recorded 2026-09-04; ownership and staging resolution confirmed in the discovery session)
- Context and the options weighed: ADR-0002 (2026-09-12, accepted) decided session-cookie auth with e-mail + password first, explicitly no cloud identity provider (RODO rationale), and the api implements it (argon2). The readiness plan §4 targets Google OAuth via Better Auth for public access. Options: Google supersedes, password-first wins, or staged.
- Decision and why: staged. ADR-0002 stays active and rules the current api increment. Google OAuth via Better Auth — sessions in PostgreSQL, verified addresses on a required allowlist (empty list admits no one), no custom passwords, identity from the session never a submitted userId — applies when the product is exposed publicly, per readiness plan §4.
- Consequences, and what would make us revisit it: two auth stages; migrating any existing passwordHash users happens in the public-access slice, whose design supersedes ADR-0002 explicitly. Revisit if the public-access slice moves away from Google (no alternative IdP decided).
- Status: active
